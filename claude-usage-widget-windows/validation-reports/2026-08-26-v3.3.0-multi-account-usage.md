# Validation Report — v3.3.0 Multi-Account Usage Display

**Date**: 2026-08-26
**Spec**: `specs/011-multi-account-usage.md`
**Scope**: `src/accounts.py` (new), `src/oauth.py`, `src/usage_cache.py`, `src/tui.py`

## Executive Summary

Every configured Claude Code login is now discovered automatically and reported
on its own line, replacing a display that only ever read the default credential
store. Discovery keys on the directory convention that `CLAUDE_SECURESTORAGE_CONFIG_DIR`
creates — the default `~/.claude` plus each `~/.claude-credentials/<name>/` —
because that env var is per-process and cannot be enumerated from outside.
Reviewers should look first at `accounts.py` (the only new module) and at the
conversion of `oauth.py`'s module-global backoff scalars into per-store state,
which is what keeps one failing account from suppressing another.

## Phase 4 — Code Quality

- `accounts.py` is dependency-free (no Qt, no network, no I/O beyond reading a
  JSON file), so it is unit-testable in isolation and copyable verbatim into
  `peripheral-battery-monitor` — the same arrangement `usage_shape.py` already
  uses under spec 009/015.
- Backoff state moved from five module-level scalars to one `_AccountState`
  keyed by store directory. This removed the `global` statements from
  `fetch_claude_usage` entirely.
- No duplication introduced: `build_line` / `build_tui_view` gained a `label`
  parameter rather than being forked into multi-account variants.
- Single-account behavior is preserved by construction (`account_labels`
  returns the literal `Claude` for one account), not by a parallel code path.

## Phase 5 — Security Review

- **Dependency scan**: `pip-audit -r requirements.txt` → *No known
  vulnerabilities found*. `requirements.txt` is unchanged by this work; no new
  dependency was added.
- **Secrets**: no credential literals introduced. `accounts.py` reads
  credential files but extracts only `subscriptionType` — it never reads,
  returns or logs a token.
- **Logging**: new log fields carry `store` (a directory path) and account
  names only. No token, refresh token or credential body is logged.
- **Path traversal**: cache filenames are derived from account names through
  `_slug()`, which strips everything outside `[A-Za-z0-9-_]`, so a profile
  directory named `../..` cannot escape the cache directory.
- **Credential write-back**: refreshed tokens are now written to the store they
  were read from, never unconditionally to the default store — the defect this
  change had to avoid. An explicit `os.chmod(path, 0o600)` was added after the
  write so the file mode is asserted rather than inherited.
- **Verified post-change**: both credential stores remain `-rw-------`.

## Phase 5.5 — Release Safety

- **Rollback**: revert the commit. There is no migration, no schema and no
  persisted state to unwind; the display falls back to reading the default
  store alone.
- **Additive**: `fetch_claude_usage()`, `fetch_usage_cached()`, `build_line()`
  and `build_tui_view()` all keep working with their previous call signatures
  (the new parameters default to the previous behavior).
- **Blast radius**: display-only. The one write path (token refresh) was made
  strictly more precise about its destination.
