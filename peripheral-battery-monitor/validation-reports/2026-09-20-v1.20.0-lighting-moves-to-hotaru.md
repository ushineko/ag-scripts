# Validation Report: v1.20.0 — the lighting moves to hotaru

- **Date**: 2026-09-20
- **Spec**: `specs/039-the-lighting-moves-to-hotaru.md`
- **Issue**: [#13](https://github.com/ushineko/ag-scripts/issues/13)
- **Version**: 1.19.0 → 1.20.0
- **Scope**: removal of `rgb_openrgb.py`, `aio_scenes.py`, `scene_service.py`,
  `scene_shortcuts.py`, `aio_liquid.py`, `aio_dashboard.py`, `aio_color.py`,
  `build_reels.py` and `aio-scene`; `aio_section.py` and
  `peripheral-battery.py` stripped of every write path; tests and README.

## Phase 3 — Tests

```
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 /usr/bin/python3 -m pytest -q
273 passed, 36 subtests passed in 8.53s
```

Down from 285 before the removal, because six test modules for deleted code
went with it and thirteen write-path tests in `test_aio_section.py` had nothing
left to test. Two were added.

`TestNoWrites` is the one that changed meaning rather than disappearing. It
began at v1.14.0 forbidding every write, narrowed at v1.16.0 to speed alone
when RGB writes became a feature, and now forbids both again plus the presence
of any removed module. A file coming back is a regression this catches.

### A defect the suite did not catch, found by running it

`_settle` — the poll's own callback — still called `_maybe_push_dashboard`
after that method was removed. **Every test passed.** The widget logged
`liquidctl_callback_failed` with an `AttributeError` twice per poll, and the
section rendered anyway because the call sat after `render_snapshot`.

The tests exercised `render_snapshot` directly and never reached the callback,
which is the gap: a unit test that stops short of the callback proves nothing
about the callback. `TestSettle` now drives `_settle` end to end, and was
confirmed to fail against the broken code before the fix landed.

This is the second time in this area that something reported success while
doing nothing, which is worth noticing as a pattern rather than as two
incidents.

## Phase 4 — Code quality

`aio_section.py` goes from 1450 lines to 750. What is left is the poll, the
rows, the sparkline, the degradation path and the cooling alert; the module
docstring now describes that rather than a write path that no longer exists.

Dead code checked with `ruff`: the two findings that remain in touched files
(`F841` in `peripheral-battery.py`, two `F401` in `test_battery_logic.py`)
predate this work and are left alone rather than swept in.

Residual gaps, deliberately:

- `aio_queue.py` stays, now serialising only the status poll against itself.
  It is more machinery than one reader needs; collapsing it is a separate
  change and not one to make in a removal commit.

## Phase 5 — Security

No credentials, no new network paths, no new file writes. The removal
*narrows* the program's reach: it no longer opens a hidraw node for writing,
no longer publishes a D-Bus object, and no longer installs a KWin script.
`ruff` reports no new findings. No secrets in the diff.

## Phase 5.5 — Release safety

Rollback is `git revert`. Nothing here is stateful and no migration runs. The
`openrgb-server` user unit is untouched — it is hotaru's dependency now, and
removing it would break the program that took over.

### The retired settings keys

They are dropped on load and the cleaned file is written once at startup. The
first attempt dropped them on load and left the write to "the next save", which
on this widget is close to never: it is looked at rather than used, and a start
that changes nothing never saves. Three tests cover it, including one asserting
a file *without* them triggers no save — a start that rewrites the settings for
no reason is a start that can lose them for no reason.

## Verified on the machine

- The widget runs, and the AIO section shows coolant, CPU, pump and fans from
  the same sources as before.
- No `liquidctl_callback_failed` in the log after the fix, across a run of
  several polls.
- hotaru's eighteen numpad shortcuts work with this program running: nine
  colours on `Ctrl+Alt+Num1..9` and nine animations on the shifted row.
- The live config lost `aio_scenes`, `aio_lcd_dashboard` and
  `lighting_last_color` on the next start, and kept everything else: bandwidth
  interfaces, slots, opacity and the section toggle all unchanged. The previous
  file is in `.bak`.

### A false negative worth recording

The first three attempts to verify this reported "nothing removed" while the
file was plainly being written. The app had exited immediately with "Another
instance is already running" — an earlier launch of mine was still up, because
the pid captured from `(timeout N cmd &)` is `timeout`'s and not the program's.
The lesson is about the evidence rather than the code: a run that produces no
change and no error deserves a look at whether it ran at all.
