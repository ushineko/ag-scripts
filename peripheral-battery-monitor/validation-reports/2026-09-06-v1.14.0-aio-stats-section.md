Baseline before this change was 138 passed. The 54 added tests are 26 in

`-p no:black -p no:flake8` is required on this machine and is not related to this
change: the installed `pytest-black` and `pytest-flake8` plugins declare a
`pytest_collect_file` hook signature that current pluggy rejects, so pytest
aborts during startup before collecting anything. Without those two flags the
suite does not start at all, at this commit or any earlier one.

### Test ordering

`tests/test_battery_logic.py` replaces the `PyQt6` namespace with mocks at import
time and restores it in `tearDownModule`. Any real-Qt module collected after it
therefore binds mocks instead of Qt. In the normal `pytest tests/` run,
`test_aio_section.py` is collected first and is unaffected. For an explicit
out-of-order invocation it now skips with a reason instead of failing:

```
/usr/bin/python3 -m pytest tests/test_battery_logic.py tests/test_aio_section.py -q ...
70 passed, 1 skipped
```

This ordering fragility predates this change. The same forced ordering with
`tests/test_claude_section_rows.py` segfaults the interpreter on this machine, at
this commit and before it. Not fixed here; out of scope for this spec.

## Phase 4 — Code quality

Two issues were found and fixed during the pass:

- **Duplication**: endpoint URL construction existed in both `read_aio` and the
  section's `_poll`. Extracted to `aio_reader.endpoint_urls()`, whose keys are
  the `build_snapshot` argument names, so the section's fan-out loop and the
  synchronous reader cannot drift apart.
- **Parsing outside the data layer**: the section decoded reply bytes with
  `json.loads` itself, contradicting the module contract that all parsing lives
  in `aio_reader`. Extracted to `aio_reader.decode_payload()`; the section no
  longer imports `json`.

Also simplified the channel-key sort from a length-then-string comparison to an
explicit numeric key with a documented fallback, and added tests covering the
three new helpers.

Checks: no unused imports in either new module; no method over 50 lines
(`_render_available` is the longest at ~30); no duplicated blocks remaining.

`aio_reader.coolant_label` is parsed and returned but not rendered. It is part of
the documented snapshot contract, appears in the CLI output, and is covered by
tests, so it is kept rather than removed as dead code.

## Phase 5 — Security review

Run separately via `/ralph-security-review`. Verdict **CONCERNS**, from
pre-existing system-package CVEs unrelated to this diff. Summary:

- **Phase A (CVE scan)**: `pip-audit 2.10.0` under `/usr/bin/python3`. 26
  vulnerabilities across `aiohttp` 3.13.3 and `msgpack` 1.1.2. Neither package is
  imported anywhere in this sub-project (`grep` confirms zero references); both
  are system-wide pacman packages, remediated by a system upgrade rather than by
  this repo. This sub-project ships no dependency manifest. The `pip-audit` in
  `~/miniforge3` is broken (missing `filelock`) and was not used; the project
  mandates system python anyway.
- **Phase B (OWASP, AI-assisted, best-effort, not compliance evidence)**: clean.
  No shell, SQL, `eval`, `pickle`, or `yaml.load`. Deserialization is `json.loads`
  only. The endpoint defaults to `127.0.0.1:27003` and is overridable only by the
  operator's own `OPENLINKHUB_API` environment variable, so there is no
  attacker-controlled URL and no SSRF surface. Every daemon-supplied field is
  treated as optional and range-checked before use. No daemon-supplied string
  reaches `QLabel.setText`: the only inputs are formatted numbers and static
  literals, so Qt's automatic rich-text detection cannot render remote content.
- **Phase C (secrets)**: 0 findings, inline scan. No scanner installed locally.
  No credentials, tokens, or credential-bearing URLs in the diff.
- **Phase D (supply chain / agent config)**: clean. No dependency manifest,
  lockfile, or agent-config path in the diff.

## Phase 5.5 — Release safety

- **Rollback**: revert the commit. The change is additive: two new modules, one
  new config key, one new menu item.
- **Runtime disable without a code change**: set `"aio_section_enabled": false`
  in `~/.config/peripheral-battery-monitor.json`, or right-click → **AIO** →
  **Show AIO Section**.
- **Config compatibility**: the new key is additive and merged over defaults on
  load. An older version ignores an unknown key, so downgrading is safe.
- **Blast radius on failure**: the section is constructed unconditionally but
  self-hides until data arrives, and every poll failure is caught. A daemon that
  is absent, broken, or hung leaves the rest of the widget untouched.
- **No new install or uninstall steps**: `install.sh` deploys the `.desktop`
  entry and the KWin rule only, and `uninstall.sh` already removes the single
  config file that holds the new key.

## Known limitations

- Fan and pump **speed control** is not offered and will not be. Commander ST
  firmware 2.x silently discards duty writes from both OpenLinkHub and liquidctl,
  so a control would report success and change nothing. A test asserts no write
  verb exists in either new module.
- Only devices OpenLinkHub can open are visible. A device whose hidraw node is
  not owned by the `openlinkhub` user does not appear.
- Coolant thresholds (50 °C / 55 °C) are taken from one cooler's observed alarm
  behaviour on this machine and are not configurable.
- The sparkline holds in-memory history only. It starts empty after a restart.
