# Validation Report — v1.12.0 Multi-account Claude usage rows

**Date**: 2026-08-26
**Spec**: `specs/016-multi-account-usage.md`
**Scope**: `accounts.py` (new, mirrored), `peripheral-battery.py`

## Executive Summary

The Claude Code section now renders one row per configured Claude login instead
of a single reading from the default credential store. The rows live inside the
existing `ClaudeSection` — there is still exactly one "Claude Code" header — and
each carries its profile name plus a one-letter account type, with the full type
on the tooltip. Reviewers should look first at `_build_claude_rows` /
`_sync_claude_rows` (row lifecycle) and at the conversion of the module-global
backoff scalars into per-store `_AccountState`, which is what keeps one failing
account from suppressing another.

`test_claude_section_rows.py` drives the real PyQt6 widgets on the offscreen
platform, constructing only the Claude section (a subclass calls `QWidget`'s
initializer directly, skipping the battery readers, KWin, tray and timers).

Updated existing tests: backoff assertions read `pb._state(None)` instead of the
removed module globals, and the Claude-label tests seed a single-account row so
the render path lands on their mocks. Both encode the same contracts as before.

**Behavior change worth noting**: last-known-good fallback is now per account.
The section-level cache is still honored, but only when exactly one account is
configured — with several it belongs to whichever account refreshed last, and
reusing it would attribute one account's usage to another.

## Phase 4 — Code Quality

- `accounts.py` is copied verbatim from `claude-usage-widget-windows`, the same
  arrangement `usage_shape.py` uses under spec 015. Its test file is mirrored
  too, so the copy drifting is caught.
- The render helpers (`_render_usage_data`, `_render_credits_data`,
  `_render_unavailable`, `_set_claude_progress`) gained a `row` parameter rather
  than being forked; a new `_render_error` replaces error-label handling that
  was previously inlined in `update_claude_section`.
- `update_claude_section` dropped from one long branching method to a short
  dispatcher plus `_update_account_row`.
- Rows are rebuilt only when the set of account names actually changes, so a
  poll does not discard each row's last-known-good reading.

## Phase 5 — Security Review

- **Dependency scan**: no dependency changes in this project; the companion
  project's `pip-audit` run (shared `structlog` / `rich` / Qt stack) reported
  *No known vulnerabilities found*.
- **Secrets**: no credential literals. `accounts.py` reads credential files but
  extracts only `subscriptionType`; it never reads, returns or logs a token.
- **Logging**: new log fields carry `store` (a directory path) and account names
  only — no credential material.
- **Credential write-back**: refreshed tokens are written to the store they came
  from rather than unconditionally to the default store, with an explicit
  `os.chmod(path, 0o600)` so the mode is asserted rather than inherited.
- **Verified post-change**: both credential stores remain `-rw-------`.

## Phase 5.5 — Release Safety

- **Rollback**: revert the commit and relaunch. Display-only change; no
  persisted state, no migration, no settings schema change.
- **Additive**: `update_claude_section` still accepts a bare payload (or None),
  the pre-spec-016 calling convention, and treats it as the default account.
- **Blast radius**: the Claude section only. Battery, bandwidth and tray paths
  are untouched.
