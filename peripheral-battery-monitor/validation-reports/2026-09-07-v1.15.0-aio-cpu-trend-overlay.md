## Phase 4 — Code quality

No new issues found; the change is a refactor plus an addition.

`Sparkline` went from a single hardcoded series to a `_Series` value class keyed
by name. The per-series scale calculation moved out of `paintEvent` into
`_Series.bounds()`, and drawing moved into `_draw_series`, so `paintEvent` is now
a loop over series. `QPainter` is constructed lazily, so a sparkline with nothing
plottable does no painting work at all.

Row colours were centralised into `_apply_row_colors()`, called from both
`update_style` (where the parent stylesheet resets child colours) and the render
path. Previously only the coolant colour needed reapplying; with CPU also
carrying a colour, two call sites setting it independently would have drifted.

No unused imports; no method over 50 lines; no duplicated blocks.

## Phase 5.5 — Release safety

- **Rollback**: revert the commit. No config key, no persisted state, no new
  dependency; sparkline history is in-memory only.
- **Blast radius**: contained to the sparkline widget and the CPU row's colour.
  A failure in the averaging or drawing path cannot reach the data layer, the
  poll cadence, or the degradation logic, all of which are unchanged.
- **Behaviour change to flag on rollback**: the graph's visibility rule. v1.15.0
  shows it whenever either trace has data; v1.14.0 hid it whenever coolant was
  absent. Reverting restores the stricter rule, which is only observable on a
  device with fans but no cooler.
- **No install or uninstall changes.**

## Known limitations

- **Heights are not comparable between the two traces.** This is the accepted
  cost of independent scaling and the main way the graph can be misread. A
  viewer could infer that the CPU line sitting above the coolant line means CPU
  is hotter. That happens to be true here, but it is not what the pixels encode.
  Mitigated by the colour-coded rows carrying real numbers directly above the
  plot, and documented in the README and the `Sparkline` docstring. Not
  eliminated.
- The 60-second averaging window is a constant, not a setting.
- Both traces still hold in-memory history only, so the graph starts empty after
  a restart.
