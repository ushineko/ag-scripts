### Phase 4: Code Quality

- `usage_shape.py` copied **byte-identical** from the widget project (md5
  `1dc00d17ca1b66689b98a4562dc01ee3` on both). Duplication is deliberate and
  documented in the spec: the two projects share no install path and the widget
  is PyInstaller-frozen, so a cross-project import would not survive packaging.
  The identical-checksum criterion is what keeps the copies from drifting
  silently.
- **Duplication removed**: the credits path needed the same progress-bar
  stylesheet as the limits path, so the value + chunk-color assignment was
  extracted to `_set_claude_progress()` and both paths now call it. The naive
  change would have left two copies of an 11-line stylesheet.
- Credits rendering reuses the three existing labels
  (`claude_five_hour_lbl` / `claude_seven_day_lbl` / `claude_duration_lbl`)
  rather than adding widgets, so the layout and `ClaudeStats` styling are
  untouched.
- `_severity_hex()` placed beside the other module-level helpers, mirroring the
  widget project's `severity_color()` while using this project's inline hex
  palette.
- `ruff check` on `usage_shape.py` and the new test class: **All checks passed**.
  Six pre-existing findings remain in `peripheral-battery.py` (lines 1573, 1662)
  and `tests/test_battery_logic.py` (lines 130, 131, 481, 537) — all confirmed
  outside every diff hunk (hunks end at ~line 1420) and left alone per
  surgical-changes.
